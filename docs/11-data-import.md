# 11 — การนำเข้าข้อมูลตอนเปิดคลินิกใหม่

> **สถานะ: ข้อกำหนด ยังไม่ได้ลงมือทำ** (ตัดสิน 2026-09-18 — คำตอบ Q4)
> คลินิกนำร่อง **ไม่มีข้อมูลเดิมให้ย้ายระบบ** เครื่องมือนี้จึงไม่ใช่ตัวแปลงจากระบบเก่า
> แต่เป็น **ตัวคีย์ข้อมูลตั้งต้นจาก Excel/Google Sheet ที่คลินิกมีอยู่แล้ว** ตอน onboarding
> (ทะเบียนลูกค้า, แค็ตตาล็อกบริการ, รายการยา, สต็อกยกมา)

## 1. หลักการ

| หลัก | เหตุผล |
| --- | --- |
| ไฟล์ CSV UTF-8 หนึ่งไฟล์ต่อหนึ่งเอนทิตี หัวคอลัมน์ต้องตรงตามเทมเพลต | คลินิกส่งออกจาก Excel ได้เอง ไม่ต้องเขียนโค้ด |
| **dry-run ก่อนเสมอ** — ตรวจครบทุกแถวแล้วรายงานผล ก่อนเขียนอะไรลงฐาน | ข้อมูลผิดตอนเปิดระบบ แก้ยากกว่าตรวจก่อน |
| **idempotent ด้วย `external_ref`** — รันไฟล์เดิมซ้ำ = อัปเดตแถวเดิม ไม่สร้างซ้ำ | คลินิกจะแก้ไฟล์แล้วอัปโหลดใหม่หลายรอบแน่นอน ([AGENTS.md §3 ข้อ 10](../AGENTS.md)) |
| หนึ่งไฟล์ = หนึ่งทรานแซกชัน แถวใดแถวหนึ่งพัง = ทั้งไฟล์ไม่เข้า | กันข้อมูลเข้าครึ่ง ๆ กลาง ๆ ที่ไล่ตามยาก |
| `tenantId` / `branchId` มาจาก session และหน้าจอที่เลือก **ไม่ใช่จากไฟล์** | [AGENTS.md §7](../AGENTS.md) — ผูก tenant จากไฟล์ = ข้อมูลข้ามคลินิก |
| ทุกครั้งที่นำเข้าเขียน `AuditLog` พร้อมเลขที่ชุดนำเข้า | ต้องตอบได้ว่าข้อมูลแถวนี้มาจากไฟล์ไหน ใครอัปโหลด เมื่อไร |

**ลำดับการนำเข้า** (ผูกกันตามลำดับนี้ ข้ามขั้นไม่ได้):

```
owners.csv → pets.csv → services.csv → products.csv → product_units.csv → opening_stock.csv
```

## 2. รูปแบบค่าที่ใช้ทุกไฟล์

| ชนิดข้อมูล | รูปแบบในไฟล์ | เหตุผล |
| --- | --- | --- |
| เงิน | สตริง `"1250.50"` หน่วย**บาท** | แปลงเป็นสตางค์ด้วย `bahtStringToSatang` ตอนอ่าน — ห้ามให้ float แตะเงิน ([§3 ข้อ 1](../AGENTS.md)) |
| วันที่ | `YYYY-MM-DD` **ค.ศ.** เท่านั้น | กันสับสน พ.ศ./ค.ศ. ระบบค่อยแสดงผลเป็น พ.ศ. |
| ปริมาณสต็อก | ทศนิยมไม่เกิน 4 ตำแหน่ง ในหน่วย**ฐาน** | [§3 ข้อ 7](../AGENTS.md) |
| เบอร์โทร | ตัวเลขล้วน `0812345678` (ระบบตัดขีด/ช่องว่าง/`+66` ให้) | ใช้ค้นหาและเป็นบัญชีพอร์ทัล |
| boolean | `true` / `false` (ว่าง = `false`) | |
| `external_ref` | รหัสอะไรก็ได้ที่คลินิกใช้ในไฟล์ตัวเอง ห้ามซ้ำในไฟล์เดียวกัน | กุญแจกันนำเข้าซ้ำ |

## 3. เทมเพลตไฟล์

`*` = บังคับ

| ไฟล์ | คอลัมน์ |
| --- | --- |
| `owners.csv` | `external_ref*`, `prefix`, `first_name*`, `last_name`, `nickname`, `phone_primary*`, `phone_secondary`, `email`, `address_line`, `sub_district`, `district`, `province`, `postal_code`, `tax_id`, `tax_branch_code`, `note` |
| `pets.csv` | `external_ref*`, `owner_external_ref*`, `name*`, `species_code*`, `breed_name`, `sex` (`M`/`F`/`UNKNOWN`), `is_neutered`, `birth_date`, `birth_date_is_estimate`, `color_markings`, `microchip_no`, `weight_kg`, `note` |
| `services.csv` | `code*`, `name*`, `category*` (ค่าใน `ServiceCategory`), `price_baht*`, `tax_code` (ว่าง = `VAT7`), `duration_minutes`, `is_bookable_online` |
| `products.csv` | `code*`, `barcode`, `name*`, `generic_name`, `type*` (ค่าใน `ProductType`), `category`, `dosage_form`, `strength`, `base_unit*`, `is_controlled`, `controlled_class`, `requires_prescription`, `default_price_baht*`, `cost_baht`, `tax_code` (ว่าง = `VAT7`) |
| `product_units.csv` | `product_code*`, `unit_name*`, `factor_to_base*`, `is_purchase_unit`, `is_sale_unit`, `price_baht`, `barcode` |
| `opening_stock.csv` | `branch_code*`, `product_code*`, `lot_no*`, `expiry_date`, `qty_base*`, `unit_cost_baht*`, `received_at`, `witness_staff_code` |

- `species_code` ต้องมีอยู่แล้วจาก seed ข้อมูลอ้างอิง — ถ้าไม่พบ ให้ปฏิเสธแถวนั้น ไม่สร้างชนิดสัตว์ใหม่เอง
- `breed_name` ไม่พบ → บันทึกเป็นค่าว่างพร้อมเตือน ไม่ใช่สร้างสายพันธุ์ใหม่
- `weight_kg` เข้าเป็น `PetWeight` หนึ่งแถว ลงวันที่วันที่นำเข้า ไม่ใช่เขียนทับ `Pet` อย่างเดียว
- `tax_code` ของสินค้ากลุ่มยา/อาหารสัตว์ยังรอผู้ทำบัญชียืนยัน — ดู [docs/06 §6.2](06-billing-pos-and-tax.md)

## 4. กติกาเฉพาะโดเมนที่ห้ามละเมิดตอนนำเข้า

| เรื่อง | กติกา |
| --- | --- |
| **สต็อกยกมา** | เขียนเป็น `StockMovement` ชนิด `RECEIPT` พร้อม `refType = "IMPORT"` และสร้าง `StockLot` ให้ครบ **ห้าม `UPDATE StockOnHand` ตรง ๆ** ปล่อยให้ trigger ทำ ([§3 ข้อ 6, 7](../AGENTS.md)) |
| **ยาควบคุม** | แถวที่สินค้า `is_controlled = true` ต้องมี `witness_staff_code` ไม่งั้นปฏิเสธทั้งไฟล์ — ยอดยกมาต้องมี `ControlledDrugEntry` ตั้งต้นเสมอ |
| **เอกสารการเงินเก่า** | **ห้ามนำเข้า** `Invoice` / ใบเสร็จย้อนหลัง เลขที่เอกสารต้องจองจากระบบตอนออกบิลจริงเท่านั้น ([§3 ข้อ 3, 4](../AGENTS.md)) — ถ้าคลินิกอยากเก็บของเก่า ให้แนบเป็นไฟล์ PDF ที่ระดับลูกค้า |
| **เวชระเบียนเก่า** | ถ้ามีในอนาคต ให้เข้าเป็นบันทึกนำเข้าแบบอ่านอย่างเดียว **ห้ามแปลงเป็น `SoapNote` ที่ `signedAt` ไม่ null** เพราะไม่มีใครลงนามจริง ([§3 ข้อ 5](../AGENTS.md)) |
| **PDPA** | ไม่รับคอลัมน์เลขบัตรประชาชน และ**ไม่นำเข้าคำยินยอม** — ต้องเก็บ consent ใหม่ผ่านระบบ ([docs/08](08-security-and-pdpa.md)) |
| **ยอดหนี้ค้าง / มัดจำเก่า** | ยังไม่รองรับในเวอร์ชันนี้ ถ้าจำเป็นให้เปิดเป็นคำถามใหม่ ไม่ใช่เดาวิธีลง |

## 5. ขั้นตอนบนหน้าจอ

1. เลือกสาขา → เลือกชนิดไฟล์ → อัปโหลด CSV
2. ระบบ **dry-run**: ตรวจหัวคอลัมน์, ชนิดข้อมูล, การอ้างอิงข้ามไฟล์, ค่าซ้ำ
3. แสดงผล: จำนวนแถวที่จะ **สร้างใหม่ / อัปเดต / ปฏิเสธ** + ตารางแถวที่ผิดพร้อมเหตุผลรายแถว (ดาวน์โหลดกลับเป็น CSV ได้)
4. กดยืนยัน → เขียนจริงในทรานแซกชันเดียว → สรุปผล + เลขที่ชุดนำเข้า
5. ย้อนกลับ: ข้อมูลหลัก (ลูกค้า/สัตว์/แค็ตตาล็อก) ลบตามชุดนำเข้าได้ถ้ายังไม่ถูกใช้
   ส่วน **สต็อกยกมาย้อนกลับด้วยการลงรายการกลับทาง** ไม่ใช่ลบ ledger

## 6. ต้องอนุมัติก่อนลงมือ (แก้สคีมา)

เครื่องมือนี้ต้องการของที่ **ยังไม่มีในสคีมา** — ต้องได้ไฟเขียวจากผู้ใช้ก่อน
([AGENTS.md §2, §8 ข้อ 4](../AGENTS.md)) และทุกฟิลด์ต้องมี `@map("snake_case")`

1. `externalRef String? @map("external_ref")` + `@@unique([tenantId, externalRef])`
   บน `Owner`, `Pet`, `Product`, `ServiceItem`
2. ตาราง `ImportBatch` — ใครอัปโหลด, ไฟล์อะไร, กี่แถว, ผลลัพธ์, เวลา (ผูกกับ `AuditLog`)
