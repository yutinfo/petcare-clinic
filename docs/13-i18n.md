# 13 — รองรับสองภาษา (ไทย / อังกฤษ) 100%

> **สถานะ: เอกสารออกแบบ ยังไม่ได้ลงมือทำ** (2026-09-18)
> วันนี้ข้อความทุกบรรทัดในระบบเป็นภาษาไทยที่ฝังอยู่ในไฟล์ `.tsx` และ `.ts` โดยตรง
> ไม่มีคลังข้อความ ไม่มีการเลือกภาษา — เอกสารนี้คือแผนเปลี่ยนให้รองรับสองภาษาเต็มรูป
> อ่านคู่กับ [docs/12 คอนโซลผู้ดูแล](12-admin-console.md) และ [docs/09 สัญญา API](09-api-contract.md)

## 1. "100%" หมายถึงอะไร

| ต้องเป็นสองภาษา | ไม่แปล (คงตามที่ผู้ใช้พิมพ์) |
| --- | --- |
| ข้อความ UI ทุกตัวในแอปพนักงาน พอร์ทัล และคอนโซลผู้ดูแล | เนื้อหาเวชระเบียน (SOAP, `CareLog`, บันทึกอาการ) — เป็นหลักฐานทางกฎหมาย **ห้ามแปลอัตโนมัติ** |
| ข้อความ error และข้อความยืนยันทุกอัน | ชื่อลูกค้า ชื่อสัตว์ ที่อยู่ — เก็บตามที่กรอก |
| ป้ายของค่า enum ทุกตัว (`ProductType`, `ServiceCategory`, สถานะทุกชนิด) | หมายเหตุที่พนักงานพิมพ์เอง (`reason`, `note`) |
| ชื่อบริการ สินค้า แพ็กเกจ บทบาท โซนกรง | เลขที่เอกสาร รหัสสินค้า รหัสสาขา |
| ข้อมูลอ้างอิง: ชนิดสัตว์ สายพันธุ์ รหัสวินิจฉัย | ข้อความคำยินยอม PDPA ฉบับกฎหมาย (แปลได้ แต่ต้องให้ที่ปรึกษากฎหมายรับรองทั้งสองฉบับ) |
| เทมเพลตแจ้งเตือนทุกช่องทาง | |
| เอกสารพิมพ์: ใบกำกับ/ใบเสร็จ, ทะเบียนยาควบคุม, ใบรับรองสุขภาพ | |

**เกณฑ์ตัดสินว่า "100%" แล้วจริง** — ดู §11

## 2. ภาษาและการเลือกภาษา

| ค่า | รายละเอียด |
| --- | --- |
| ภาษาที่มากับระบบ | `th` (ค่าเริ่มต้น) และ `en` |
| ภาษาเพิ่ม | เพิ่มโดยนำเข้าคลังข้อความและแถวคำแปล ไม่เพิ่มคอลัมน์ต่อภาษา |
| ใครสลับภาษาได้ | ผู้ใช้ทุกคนที่เข้าใช้งาน ทั้งพนักงานและเจ้าของสัตว์ในพอร์ทัล |
| หน่วยเวลา | ทุก locale ใช้เขตเวลา `Asia/Bangkok` เสมอ ไม่ผูกกับภาษา |
| ปฏิทิน | `th` = พุทธศักราช · `en` = คริสต์ศักราช |

**ลำดับการตัดสินภาษา** (ตัวแรกที่มีค่าชนะ)

| บริบท | ลำดับ |
| --- | --- |
| แอปพนักงาน | `User.locale` (ยังไม่มีฟิลด์ — G1) → คุกกี้ `pc_locale` → `Tenant.locale` → `th` |
| พอร์ทัลเจ้าของสัตว์ | `?lang=` บน URL → `Owner.locale` (G1) → คุกกี้ → `Tenant.locale` → `Accept-Language` → `th` |
| การแจ้งเตือน (อีเมล/SMS/LINE) | `Owner.locale` → `Tenant.locale` → `th` — **ไม่ใช้ภาษาของคนที่กดส่ง** |
| เอกสารพิมพ์ | ภาษาที่ล็อกไว้บนเอกสารตอนออก (G3) → ภาษาของลูกค้า → `Tenant.locale` |
| งานเบื้องหลัง (BullMQ) | ภาษาของผู้รับปลายทางเท่านั้น — worker ไม่มี "ภาษาปัจจุบัน" |

`?lang=` ที่ URL ของพอร์ทัลใช้เพื่อให้ลิงก์ในอีเมลเปิดมาเป็นภาษาเดียวกับอีเมล และต้องเขียนค่าลงคุกกี้ให้ผู้ใช้ต่อเนื่อง

ตัวสลับภาษาอยู่กับทุกคนที่เข้าใช้งาน คลินิกกำหนดภาษาเริ่มต้นของร้านได้ แต่ปิดปุ่มสลับของเจ้าของสัตว์หรือพนักงานไม่ได้

## 3. คลังข้อความของ UI

### 3.1 โครงไฟล์

```
src/lib/i18n/
├─ messages/th.json          ← ต้นฉบับ นักพัฒนาเขียนที่นี่ก่อนเสมอ
├─ messages/en.json          ← ต้องมีคีย์ครบเท่ากับ th.json
├─ index.ts                  ← โหลด/เลือก locale, ฟังก์ชัน t()
└─ format.ts                 ← วันที่ ตัวเลข เงิน ตามภาษา
```

### 3.2 การตั้งชื่อคีย์ — บังคับรูปแบบนี้

```
<โดเมน>.<หน้าจอหรือบริบท>.<องค์ประกอบ>
pharmacy.dispense.button.confirm
billing.invoice.warning.issued_locked
common.action.save
enum.ProductType.DRUG
error.STOCK_INSUFFICIENT
```

- ป้ายของ enum ใช้ `enum.<ชื่อ enum>.<ค่า>` เสมอ เพื่อให้เพิ่มค่าใหม่แล้วรู้ทันทีว่าต้องแปลอะไร
- ข้อความ error ใช้ `error.<CODE>` โดย `CODE` ตรงกับ `BusinessError.code` ใน [`src/modules/shared/errors.ts`](../src/modules/shared/errors.ts)
- ห้ามตั้งคีย์ตามข้อความ (`"บันทึกสำเร็จ"`) เพราะข้อความเปลี่ยนแล้วคีย์เน่า

### 3.3 กติกาที่ห้ามละเมิด

1. **ห้ามเขียนข้อความที่ผู้ใช้เห็นลงในไฟล์คอมโพเนนต์โดยตรง** ทุกข้อความมาจากคลังข้อความ
2. `src/modules/**` **ห้ามคืนประโยคสำเร็จรูป** ให้คืน `code` + พารามิเตอร์ แล้วให้ชั้น UI แปล (ดู §4)
3. ห้ามต่อสตริงเอง (`"พบ " + n + " รายการ"`) ใช้พารามิเตอร์ในคีย์ และใช้รูปพหูพจน์แบบ ICU สำหรับ `en`
4. ห้ามใช้ข้อความเป็นตัวตัดสินตรรกะ — เทียบด้วยค่า enum หรือ code เท่านั้น
5. คีย์ที่ไม่มีใน `en.json` **ทำให้ CI ล้ม** ไม่ใช่แค่เตือน (นี่คือความหมายของ 100%)

### 3.4 ไลบรารี — ต้องให้ผู้ใช้อนุมัติก่อน (เปลี่ยนสแต็ก [AGENTS.md §2](../AGENTS.md))

| ทางเลือก | ได้อะไร | เสียอะไร |
| --- | --- | --- |
| **A. `next-intl`** (แนะนำ) | รองรับ App Router + Server Component โดยตรง, ICU plural/select, formatter วันที่-ตัวเลขในตัว, ตรวจคีย์ด้วย TypeScript ได้ | เพิ่ม dependency + ต้องวาง provider ที่ layout |
| B. เขียนเองบาง ๆ (~150 บรรทัด) | ไม่มี dependency ใหม่ คุมได้ทุกบรรทัด | ต้องทำ plural/format เอง ซึ่งภาษาอังกฤษมีเอกพจน์-พหูพจน์ที่พลาดง่าย |

**ข้อเสนอ:** เลือก A เพราะงานส่วนใหญ่คือ Server Component และต้องการ plural ที่ถูกต้อง
ถ้าผู้ใช้ไม่อยากเพิ่ม dependency ให้ใช้ B โดยยังคงรูปแบบคีย์และกติกาใน §3.2-3.3 เหมือนกันทุกข้อ

## 4. ข้อความจากฝั่งเซิร์ฟเวอร์

วันนี้ `BusinessError` ถือข้อความไทยไว้ในตัว เช่น `` throw new Error(`${field} ต้องเป็นจำนวนเต็มหน่วยสตางค์`) ``
แบบนี้แปลไม่ได้ ต้องเปลี่ยนเป็น:

```ts
// modules/ — คืนรหัสและพารามิเตอร์ ไม่ใช่ประโยค
throw new BusinessError("SATANG_NOT_INTEGER", { field: "unitPriceSatang" });

// UI — แปลตรงจุดที่แสดงผล
t(`error.${err.code}`, err.params);
```

| ผลกระทบ | สิ่งที่ต้องทำ |
| --- | --- |
| `src/modules/shared/errors.ts` | เพิ่มช่อง `params` และบังคับให้ `code` เป็น union ที่ประกาศไว้ ไม่ใช่ string อิสระ |
| [docs/09 §3 รูปแบบ error](09-api-contract.md) | API คืน `{ code, params }` และ `message` เป็นภาษาของผู้เรียก (จาก `Accept-Language`) ไว้ดีบักเท่านั้น |
| zod | ใช้ error map กลางที่แปลง issue code ของ zod เป็นคีย์ `error.validation.*` |
| ข้อความใน `AuditLog.reason` | เก็บตามที่ผู้ใช้พิมพ์ ไม่แปล |

## 5. ข้อมูลในฐานข้อมูล

### 5.1 ที่มีสองภาษาอยู่แล้ว

| ตาราง | ฟิลด์ |
| --- | --- |
| `Species` | `nameTh`, `nameEn` (บังคับทั้งคู่) |
| `Breed` | `nameTh`, `nameEn` (EN ยังว่างได้) |
| `DiagnosisCode` | `nameTh`, `nameEn` (EN ยังว่างได้) |
| `NotificationTemplate` | มีคอลัมน์ `locale` และ unique `(tenantId, key, channel, locale)` อยู่แล้ว — เติมแถว `en` ได้ทันที |

### 5.2 ที่ยังขาด (G2)

| ตาราง | ฟิลด์ที่ผู้ใช้เห็น | ข้อเสนอ |
| --- | --- | --- |
| `ServiceItem` | `name`, `description` | แถวคำแปลตาม locale ไม่เพิ่ม `nameEn` |
| `ServicePackage` | `name`, `description` | แถวคำแปลตาม locale |
| `Product` | `name` (+ `dosageForm`, `strength` ที่พิมพ์บนฉลากยา) | ชื่อเป็นแถวคำแปล; `dosageForm` ใช้ค่าคงที่แล้วแปลผ่าน `enum.*` |
| `Role` | `name` (บทบาทที่คลินิกสร้างเอง) | แถวคำแปลตาม locale; บทบาทสำเร็จรูปแปลผ่าน `enum.Role.<key>` |
| `KennelProfile` | `zone`, `features` | ทำเป็นค่าที่เลือกจากรายการ แล้วแปลผ่าน `enum.*` |
| `ConsentForm` / `OwnerConsent` | เนื้อความคำยินยอมที่ผู้ลงนามเห็น | ทั้งสองตารางเก็บ**ข้อความที่ลงนามจริง**ไว้แล้ว (`bodySnapshot` / `version`) สิ่งที่ขาดคือ **ต้นฉบับเทมเพลตคำยินยอมแยกภาษา** ซึ่งวันนี้ยังไม่มีตารางรองรับ — ดู G5 |

คอลัมน์ `nameTh` / `nameEn` ที่มีอยู่แล้วใน `Species`, `Breed`, `DiagnosisCode` ไม่รื้อ. ชื่อที่ยังไม่มีคอลัมน์ภาษาเก็บเป็นแถว `locale` + ข้อความ เพื่อให้นำเข้าภาษาที่สามได้โดยไม่เพิ่มคอลัมน์. ภาษาไทยบนตัวเรคคอร์ดยังเป็นข้อความหลัก เมื่อภาษานั้นยังไม่มีคำแปลให้แสดงไทย.

### 5.3 กฎ fallback ของข้อมูล

- ภาษาอังกฤษว่าง → **แสดงภาษาไทย** ห้ามแสดงช่องว่างเด็ดขาด
- หน้าจอในคอนโซลผู้ดูแลต้องติดป้าย "ยังไม่แปล" และมีตัวกรองหาแถวที่ยังไม่แปล (ADM-06, ADM-07, ADM-18)
- ข้อมูลอ้างอิงกลางของระบบ (`tenantId = null`) ต้องมีครบสองภาษาก่อน seed ผ่าน

## 6. การค้นหาสองภาษา

`search_key` วันนี้สร้างจาก trigger `th_normalize()` ซึ่งตัดช่องว่าง ขีด จุด แล้ว lower-case — ใช้กับอังกฤษได้อยู่แล้ว
แต่**ยังไม่ได้รวมชื่อภาษาอังกฤษเข้าไป**

| ต้องแก้ | รายละเอียด |
| --- | --- |
| trigger ของ `Product` / `ServiceItem` | ต่อชื่อไทยกับคำแปลทุก locale ที่นำเข้า เข้า `search_key` เดียวกัน เพื่อให้พิมพ์ "amoxi" หรือ "อะม็อกซี่" แล้วเจอตัวเดียวกัน |
| `Owner` / `Pet` | ไม่ต้องแก้ ชื่อคนและสัตว์ไม่มีคู่แปล |
| `pg_trgm` | ใช้ได้กับทั้งสองภาษา ไม่ต้องเปลี่ยนดัชนี |

**ห้ามใช้ `to_tsvector` กับภาษาไทย** ([AGENTS.md §7](../AGENTS.md)) — ข้อนี้ไม่เปลี่ยน

## 7. เอกสารที่พิมพ์ออกไป ⚠️ กระทบกฎหมาย

| เอกสาร | ภาษา |
| --- | --- |
| ใบกำกับภาษี / ใบเสร็จรับเงิน | **ภาษาไทยต้องอยู่เสมอ** ป้ายทุกตัวมีภาษาที่สองคู่กัน ทั้งหัวข้อ ชื่อคอลัมน์ และข้อความท้ายบิล ค่าที่ไม่ใช่ป้าย (ชื่อคน ชื่อสัตว์ ตัวเลข) ไม่แปลเป็นป้าย |
| จำนวนเงินเป็นตัวอักษร | `th` ใช้ `bahtText` ที่มีอยู่แล้ว · `en` ใช้รูปแบบ "… baht … satang" — ถ้าพิมพ์สองภาษาให้แสดงไทยเป็นบรรทัดหลัก |
| ทะเบียนยาควบคุม ([docs/05 §6.1](05-inventory-and-pharmacy.md)) | ไทยเท่านั้น เพราะยื่นหน่วยงานกำกับ — ปุ่มเลือกภาษาต้องไม่มีในหน้านี้ |
| ใบรับรองสุขภาพสัตว์ / เอกสารเดินทาง | ต้องมีฉบับอังกฤษ เพราะใช้กับการส่งออก/สายการบิน |
| ใบสั่งยาและฉลากยา | ตามภาษาของเจ้าของสัตว์ แต่ชื่อยาและความแรงพิมพ์เป็นอังกฤษเสมอ (กันอ่านผิด) |

**ต้องล็อกภาษาไว้กับเอกสาร (G3)** — ใบกำกับที่ออกแล้วต้องพิมพ์ซ้ำได้เหมือนเดิมทุกตัวอักษร
ถ้าไม่เก็บว่าออกด้วยภาษาอะไร การพิมพ์ซ้ำจะได้เอกสารคนละหน้าตากับต้นฉบับ ซึ่งขัดกับหลักเอกสารที่ออกแล้วห้ามเปลี่ยน
([AGENTS.md §3 ข้อ 3](../AGENTS.md))

ผู้ใช้ตอบเมื่อ 2026-09-25 ว่าป้ายทุกตัวบนใบกำกับภาษีเต็มรูปใส่ภาษาที่สองคู่กับไทยได้. จำนวนเงินตัวอักษรยังใช้ไทยเป็นบรรทัดหลัก. ทะเบียนยาควบคุมยังเป็นไทยอย่างเดียวเพราะเป็นเอกสารคนละชนิด.

| **ADM-18 ความครบของการแปล** (`settings/translations`) | แสดง % ความครบของคีย์ UI และของข้อมูล (บริการ/สินค้า/สายพันธุ์/รหัสวินิจฉัย) พร้อมลิงก์ไปแก้รายแถว |
| ADM-06 / ADM-07 | ช่องคำแปลตาม locale ที่นำเข้าได้ และตัวกรอง "ยังไม่แปล" |
| ADM-12 | จัดการเทมเพลตแยกตาม `locale` และเตือนเมื่อมีเฉพาะ `th` |
| ADM-11 | ตั้งค่า `Tenant.locale` เป็นภาษาเริ่มต้น ตัวสลับภาษายังอยู่ให้ทุกคนที่เข้าใช้งาน |

## 10. ช่องว่างที่ต้องปิดก่อนลงมือ (แก้สคีมา — ต้องอนุมัติ)

ทุกฟิลด์ต้องมี `@map("snake_case")` ([AGENTS.md §6](../AGENTS.md))

| # | สิ่งที่ขาด | ข้อเสนอ |
| --- | --- | --- |
| G1 | ภาษาประจำตัวผู้ใช้ | `User.locale String?` และ `Owner.locale String?` (null = ใช้ของ tenant) |
| G2 | คำแปลแค็ตตาล็อกที่นำเข้าภาษาเพิ่มได้ | แถว `(entity, field, locale, text)` ของ `ServiceItem`, `ServicePackage`, `Product`, `Role` ไม่เพิ่มคอลัมน์ต่อภาษา (ดู §5.2) |
| G3 | ภาษาที่ใช้ออกเอกสาร | `Invoice.printedLocale` (และเอกสารการเงินอื่นที่พิมพ์ได้) บันทึกตอนออก ห้ามแก้ภายหลัง |
| G4 | `search_key` ยังไม่รวมชื่ออังกฤษ | แก้ trigger ของ `Product` และ `ServiceItem` |
| G5 | ต้นฉบับข้อความคำยินยอมแยกภาษา (วันนี้ `ConsentForm.bodySnapshot` เก็บเฉพาะข้อความที่ลงนามไปแล้ว ไม่มีที่เก็บต้นฉบับ) | ตาราง `ConsentTemplate` (`tenantId`, `key`, `version`, `locale`, `body`, `isActive`, `@@unique([tenantId, key, version, locale])`) + เพิ่ม `ConsentForm.locale` และ `OwnerConsent.locale` เพื่อรู้ว่าลงนามด้วยภาษาใด |

## 11. นิยาม "เสร็จ" และการทดสอบ

| เกณฑ์ | วิธีพิสูจน์ |
| --- | --- |
| คีย์ครบ 100% | เทสเปรียบเทียบคีย์ `th.json` กับ `en.json` — ขาดข้างใดข้างหนึ่ง = เทสแดง |
| ไม่มีข้อความฝังในคอมโพเนนต์ | ESLint rule ห้ามอักขระไทยใน literal ของไฟล์ `src/app/**` และ `src/components/**` (ยกเว้นไฟล์คลังข้อความ) |
| โมดูลไม่คืนประโยค | ESLint rule ห้ามอักขระไทยใน `src/modules/**` ยกเว้นคอมเมนต์ |
| ข้อมูลอ้างอิงครบสองภาษา | เทสหลัง seed: `Species` / `DiagnosisCode` ที่ `tenantId = null` ต้องมี `nameEn` ครบทุกแถว |
| เอกสารพิมพ์ถูกภาษา | เทส snapshot ของใบกำกับทั้ง `th` และ `en` และเทสว่าออกบิลด้วย `en` แล้วพิมพ์ซ้ำได้เหมือนเดิม |
| การแจ้งเตือนใช้ภาษาผู้รับ | เทส: เจ้าของตั้ง `en` แล้วเจ้าหน้าที่ที่ใช้ `th` กดส่ง → ข้อความที่ส่งต้องเป็น `en` |
| ผู้ใช้สลับภาษาได้จริง | เทส e2e: สลับภาษาแล้วเมนู ปุ่ม และข้อความ error เปลี่ยนครบทั้งหน้า |

**ห้ามประกาศว่า "รองรับสองภาษาแล้ว" ถ้าเทสเหล่านี้ยังไม่เขียวจริง** ([AGENTS.md §9, §11](../AGENTS.md))

## 12. ลำดับการส่งมอบ

| ระยะ | งาน | ผลลัพธ์ที่วัดได้ |
| --- | --- | --- |
| **A. วางราง** | เลือกไลบรารี (§3.4) → สร้าง `src/lib/i18n/` → ตัวสลับภาษา + คุกกี้ → ย้ายข้อความของ 3 หน้าแรก (login, แดชบอร์ด, เคาน์เตอร์) | สลับภาษาได้จริงใน 3 หน้า + เทสคีย์ครบเริ่มทำงาน |
| **B. ล้างข้อความฝัง** | ย้ายข้อความที่เหลือทุกหน้า + ป้าย enum + เปลี่ยน `BusinessError` เป็น code/params (§4) | ESLint rule เปิดใช้ได้โดยไม่มี error ค้าง |
| **C. ข้อมูลและเอกสาร** | G1-G5 + คอนโซล ADM-18 + เทมเพลตแจ้งเตือน `en` + เอกสารพิมพ์สองภาษา | ออกบิลภาษาอังกฤษให้ลูกค้าต่างชาติได้ครบวงจร |
| **D. พอร์ทัล** | `?lang=`, ลิงก์ในอีเมลตรงภาษา, ข้อความคำยินยอมสองภาษา | เจ้าของสัตว์ต่างชาติใช้พอร์ทัลได้ตั้งแต่ OTP จนถึงใบเสร็จ |

**ทำระยะ A ให้จบก่อนเขียนหน้าจอใหม่ทุกหน้า** ไม่งั้นงานที่ทำระหว่างนี้จะกลายเป็นหนี้ที่ต้องกลับมารื้อ
โดยเฉพาะคอนโซลผู้ดูแล 17 หน้าใน [docs/12](12-admin-console.md) ที่ยังไม่ได้เริ่ม
