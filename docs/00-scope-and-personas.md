# 00 — ขอบเขต, ผู้ใช้งาน และข้อกำหนด

## 1. ขอบเขตระบบ (Scope)

### อยู่ในขอบเขต

| โดเมน | ความสามารถหลัก |
| --- | --- |
| ทะเบียนเจ้าของ & สัตว์เลี้ยง | ประวัติเจ้าของ, สัตว์หลายตัวต่อเจ้าของ, โอนย้ายเจ้าของ, น้ำหนัก, แพ้ยา, ไมโครชิป |
| การรับเคส (Reception) | เช็คอิน, คิว, triage, whiteboard สถานะเคสแบบเรียลไทม์ |
| เวชระเบียน (EMR) | SOAP, vital signs, ปัญหา/การวินิจฉัย, สั่ง lab/x-ray/หัตถการ, แนบไฟล์, ใบยินยอม |
| ยา & การรักษา | ใบสั่งยา, จ่ายยา (ตัดสต็อก + ฉลากยา), ตารางให้ยาผู้ป่วยใน (MAR), วัคซีน + ใบรับรอง |
| นัดหมาย | นัดตรวจ, นัดวัคซีน, นัดติดตามผล, จัดตารางหมอ/ห้องตรวจ, waitlist |
| ฝากเลี้ยง (Boarding) | จองห้อง/กรง, เช็คอิน-เช็คเอาท์, บันทึกดูแลรายวัน, ของฝากติดตัว, คิดค่าห้องอัตโนมัติ |
| ผู้ป่วยใน (IPD) | ใช้กรงร่วมกับ boarding, แผนการรักษา, MAR, ค่าใช้จ่ายสะสม |
| อาบน้ำ-ตัดขน | จองคิวช่างกรูมมิ่ง, สไตล์/เบอร์ปัตตาเลี่ยน, รูปก่อน-หลัง, นัดครั้งถัดไป |
| คลังสินค้า & เภสัช | ล็อต/วันหมดอายุ (FEFO), หน่วยนับหลายชั้น, จุดสั่งซื้อ, PO/รับของ, ตรวจนับ, โอนสาขา, ทะเบียนยาควบคุม |
| ขายหน้าร้าน (POS) | ขายอาหาร/ของใช้/ยา, บาร์โค้ด, ส่วนลด, ขายพ่วงเข้าบิลเคสได้ |
| การเงิน | บิลรวม, มัดจำ, ชำระหลายวิธี, ใบกำกับภาษี, ใบลดหนี้, ปิดกะเงินสด |
| พอร์ทัลลูกค้า | ดูประวัติสัตว์, จองนัด/ห้องฝาก/กรูมมิ่ง, ดูใบเสร็จ, ดาวน์โหลดใบรับรองวัคซีน |
| แจ้งเตือน | เตือนนัด, เตือนวัคซีนครบกำหนด, เตือนยาใกล้หมด, แจ้งสถานะสัตว์ที่ฝาก |
| รายงาน | รายได้แยกหมวด/สาขา/หมอ, อัตราครองกรง, สินค้าใกล้หมดอายุ, ลูกค้าหายไป |
| แอดมินแพลตฟอร์ม | จัดการคลินิก, แพ็กเกจ, feature flag, การใช้งาน |

### ไม่อยู่ในขอบเขต (เฟสแรก)

- เชื่อมเครื่องตรวจ lab โดยตรง (ASTM/HL7) — เฟสแรกใช้แนบไฟล์ + คีย์ค่า
- PACS / DICOM viewer เต็มรูปแบบ — เฟสแรกเก็บเป็นไฟล์แนบ
- บัญชีแยกประเภทเต็มรูปแบบ — ส่งออกไฟล์ให้โปรแกรมบัญชีแทน
- เงินเดือน/HR, ระบบสมาชิกแบบแต้มซับซ้อน
- แอปมือถือ native — ใช้ PWA ของพอร์ทัลก่อน

## 2. ผู้ใช้งาน (Personas) และสิ่งที่เขาต้องการ

| Persona | บทบาท | งานหลักที่ระบบต้องทำให้เร็ว |
| --- | --- | --- |
| **คุณนุ่น** — เจ้าหน้าที่ต้อนรับ | `RECEPTIONIST` | ค้นเจ้าของจากเบอร์โทรใน 1 วินาที, เช็คอิน, รับนัด, รับเงิน, ออกใบเสร็จ |
| **หมอเอก** — สัตวแพทย์ | `VET` | เปิดเคสแล้วเห็นประวัติ/แพ้ยา/น้ำหนักทันที, บันทึก SOAP เร็ว, สั่งยาแล้วคิดขนาดยาตามน้ำหนักให้ |
| **พี่แนน** — ผู้ช่วยสัตวแพทย์ | `VET_TECH` | บันทึก vital, ทำ MAR ผู้ป่วยใน, เตรียมยา, บันทึกดูแลสัตว์ที่ฝาก |
| **ช่างบี** — ช่างกรูมมิ่ง | `GROOMER` | เห็นคิวของตัวเองวันนี้, โน้ตสไตล์ตัดของสัตว์ตัวนั้น, ถ่ายรูปก่อน-หลัง |
| **พี่โจ** — ดูแลคลัง/เภสัช | `PHARMACY` | รับของเข้าล็อต, เช็คของใกล้หมดอายุ, ตรวจนับ, ทะเบียนยาควบคุม |
| **คุณแอน** — ผู้จัดการสาขา | `BRANCH_MANAGER` | ดูรายได้วันนี้, อัตราครองกรง, อนุมัติส่วนลด, ปิดกะ |
| **เจ้าของคลินิก** | `OWNER_ADMIN` | ภาพรวมทุกสาขา, ตั้งราคา, จัดการสิทธิ์พนักงาน |
| **คุณแพร** — เจ้าของสัตว์ | `PET_OWNER` (portal) | จองคิวออนไลน์, ดูวันนัด, ดูประวัติวัคซีน, ดูบิล |
| **ทีมแพลตฟอร์ม** | `PLATFORM_ADMIN` | เปิดคลินิกใหม่, ดูแลระบบ, สนับสนุนลูกค้า |

## 3. User story ที่ใช้ตัดสินใจออกแบบ

> **US-01** ลูกค้า walk-in พาแมวมา ไม่เคยมาก่อน — เจ้าหน้าที่ต้องสร้างเจ้าของ + สัตว์ + เปิดเคส
> ได้ภายในหน้าจอเดียว ไม่เกิน 60 วินาที

> **US-07** หมอสั่ง Amoxicillin 20 mg/kg PO q12h × 7 วัน ให้สุนัข 12.4 กก. —
> ระบบคำนวณจำนวนเม็ดที่ต้องจ่าย เลือกล็อตที่หมดอายุก่อน ตัดสต็อก พิมพ์ฉลากยาภาษาไทย
> และตั้งค่าใช้จ่ายเข้าบิลอัตโนมัติ

> **US-12** สัตว์ฝากเลี้ยง 5 คืน ระหว่างนั้นขออาบน้ำ 1 ครั้ง และซื้ออาหารกลับบ้าน 1 ถุง —
> ตอนเช็คเอาท์ต้องออกเป็น **บิลเดียว** หักมัดจำที่จ่ายตอนจอง แล้วออกใบกำกับภาษีเต็มรูปได้

> **US-18** ลูกค้าจองอาบน้ำผ่านพอร์ทัลเวลา 22:00 — ระบบต้องไม่ให้จองทับคิวช่าง
> และต้องส่งคำขอเข้าคิวรออนุมัติ (หรือยืนยันอัตโนมัติตามนโยบายคลินิก)

> **US-23** ออกใบกำกับภาษีผิดชื่อบริษัท — ต้องออกใบลดหนี้/ยกเลิกแล้วออกใหม่
> โดยเลขที่เอกสารเดิมยังคงอยู่ในระบบ ไม่หายไปเป็นเลขว่าง

## 4. ข้อกำหนดที่ไม่ใช่ฟังก์ชัน (NFR)

| ด้าน | เป้าหมาย |
| --- | --- |
| ประสิทธิภาพ | ค้นหาเจ้าของ/สัตว์ p95 < 300 ms ที่ข้อมูล 500k ระเบียน; หน้าเปิดเคส p95 < 1 s |
| ความพร้อมใช้ | 99.5% ต่อเดือน; ต้องมี **โหมดออฟไลน์อ่านอย่างเดียว** สำหรับ POS ไม่ได้ในเฟส 1 แต่ต้องมี graceful error |
| ความถูกต้องทางเงิน | เงินเก็บเป็นจำนวนเต็มหน่วย *สตางค์* ห้ามใช้ float; ยอดบิล = ผลรวม line ที่ snapshot ไว้เสมอ |
| การตรวจสอบย้อนหลัง | ทุกการแก้ไขเวชระเบียน/สต็อก/เอกสารการเงิน ต้องมี audit log ระบุ ผู้ทำ-เวลา-ค่าเก่า-ค่าใหม่ |
| ความปลอดภัย | tenant isolation ระดับฐานข้อมูล (RLS), MFA สำหรับ role ระดับผู้จัดการขึ้นไป |
| ความเป็นส่วนตัว | สอดคล้อง PDPA — เก็บความยินยอม, รองรับคำขอเข้าถึง/ลบข้อมูล |
| สำรองข้อมูล | PITR ย้อนหลัง 7 วัน, snapshot รายวันเก็บ 30 วัน, ซ้อมกู้คืนทุกไตรมาส |
| ภาษา/รูปแบบ | UI ไทยเป็นค่าเริ่มต้น, เก็บเวลาเป็น UTC แสดงผล Asia/Bangkok, เลือกแสดง พ.ศ./ค.ศ. ได้ |
| การเข้าถึง | รองรับแท็บเล็ตในห้องตรวจ (ทัชสกรีน), ปุ่มเป้าหมายแตะ ≥ 44px |

## 5. ศัพท์เฉพาะ (Glossary)

| คำ | ความหมายในระบบนี้ |
| --- | --- |
| **Tenant** | คลินิก 1 กิจการ (อาจมีหลายสาขา) = ขอบเขตการแยกข้อมูล |
| **Branch** | สาขา — เป็นหน่วยของสต็อก, กรง, เลขที่เอกสารภาษี |
| **Owner** | เจ้าของสัตว์ = ลูกค้าที่จ่ายเงิน |
| **Pet / Patient** | สัตว์เลี้ยง 1 ตัว |
| **Booking** | การจองล่วงหน้า (ตรวจ / กรูมมิ่ง / ฝากเลี้ยง) — ยังไม่เกิดบริการจริง |
| **Encounter** | การมาพบสัตวแพทย์ 1 ครั้ง (เคส) — เป็นตัวรวมเวชระเบียนและค่าใช้จ่ายทางการรักษา |
| **Stay** | การเข้าพักจริงในกรง (ฝากเลี้ยง หรือ นอนโรงพยาบาล) |
| **ChargeItem** | รายการค่าใช้จ่าย 1 บรรทัดที่ยังไม่ได้วางบิล |
| **Invoice** | เอกสารเรียกเก็บ/ใบกำกับภาษีที่ออกแล้ว — แก้ไม่ได้ |
| **MAR** | Medication Administration Record — บันทึกว่าให้ยาจริงเมื่อไหร่ ใครให้ |
| **FEFO** | First-Expired-First-Out — ตัดล็อตที่หมดอายุก่อน |
